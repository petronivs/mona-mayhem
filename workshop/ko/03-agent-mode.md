# 파트 3: 에이전트 기반 워크플로(Agentic Workflows)로 게임 구현

---

이 파트에서는 Copilot이 계획을 세우는 역할에서 실제 구현을 수행하는 역할로 전환됩니다. 한 줄씩 직접 코드를 작성하는 대신 원하는 결과를 설명하면 Copilot이 필요한 파일을 찾아 작업을 수행합니다.

## 작업 1: 배틀 기능 연결

<!-- track:vscode:start -->
1. Copilot Chat에서 **Agent** 모드로 전환합니다.
2. 다음 프롬프트를 입력합니다.
<!-- track:vscode:end -->

<!-- track:cli:start -->
1. Copilot CLI를 일반 코딩 흐름으로 전환합니다. 중지할 때까지 Copilot이 계속 작업하도록 하려면 autopilot을 유지해도 됩니다.
2. 필요하면 추가 맥락을 위해 페이지 파일을 지정합니다: `@src/pages/index.astro`
3. 다음 프롬프트를 입력합니다.
<!-- track:cli:end -->

   > 배틀 페이지에 클라이언트 측 JavaScript를 추가합니다.
   > 1. Battle 버튼을 클릭하면 입력란에서 두 사용자 이름을 가져옵니다.
   > 2. 두 입력란이 모두 채워졌는지 확인하고, 비어 있으면 오류를 표시합니다.
   > 3. API를 사용해 두 사용자의 기여도 데이터를 병렬로 가져옵니다.
   > 4. GitHub 색상 팔레트를 사용해 날짜별 기여도를 색상 사각형으로 표시하는 그래프를 렌더링합니다.
   > 5. 두 사용자 사이에 VS 배지를 표시합니다.
   > 6. 각 사용자에 대해 사용자 이름, 총 기여 수, 날짜 범위를 표시합니다.
   > 7. 로딩 상태와 오류를 처리합니다.
   > 8. 입력란에서 Enter 키를 눌러도 실행되도록 합니다.
   > 9. 지금은 이미 기본 구조가 만들어진 단순한 UI를 사용합니다.
   >
   > 기여도 데이터 구조에는 TypeScript 인터페이스를 사용합니다.

4. 변경 내용을 적용하기 전에 diff 보기에서 제안된 내용을 검토합니다.

## 작업 2: 배틀 테스트

> **⚠️ 변경 사항이 보이지 않나요?** 배틀 페이지가 업데이트되지 않았다면 개발 서버를 중지(`Ctrl+C`)하고 `npm run dev`로 다시 시작한 다음 브라우저를 새로 고칩니다.

1. 두 사용자 이름으로 `octocat`과 `torvalds`를 입력한 다음 **Battle**을 클릭합니다.
2. 색상 격자로 렌더링된 두 사용자의 기여도 그래프가 나란히 표시되어야 합니다.
3. 오류 상황을 테스트합니다.
   - 한쪽 또는 양쪽 입력란을 비운 채 Battle을 클릭하면 유효성 검사 오류가 표시되어야 합니다.
   - 잘못된 사용자 이름을 입력하면 API의 오류가 앱에 표시되어야 합니다.
4. 어느 입력란에서든 **Enter** 키를 눌러 버튼 클릭과 마찬가지로 배틀이 실행되는지 확인합니다.

## 작업 3: Copilot으로 반복 개선

원하는 대로 작동하지 않는 부분이 있다면 Copilot에 직접 후속 피드백을 제공합니다. 예를 들면 다음과 같습니다.

- *"기여도 사각형이 너무 큽니다. 12x12px로 줄여 주세요."*
- *"날짜와 기여 수를 보여 주는 마우스 오버 툴팁을 추가해 주세요."*
- *"로딩 상태에 맥박 효과 애니메이션이 필요합니다."*

<!-- track:vscode:start -->
Agent 모드는 여러 파일을 바꾸거나 반복적으로 개선하는 작업을 자연스럽게 처리합니다. 후속 프롬프트는 이전 대화를 이어 가므로 처음부터 다시 시작하지 않고도 구현을 조금씩 다듬을 수 있습니다.
<!-- track:vscode:end -->

<!-- track:cli:start -->
Copilot CLI 세션은 대화 기록을 유지하므로 후속 프롬프트가 이전 작업을 이어받습니다. Copilot이 유지하는 맥락을 살펴보려면 `/session` 또는 `/context`를 사용하고, 큰 폭으로 수정한 뒤 추가로 버그나 마무리 상태를 확인하려면 `/review`를 실행합니다.
<!-- track:cli:end -->

## 이 파트의 팁

- **원하는 내용을 구체적으로 설명합니다** — 요구 사항이 명확할수록 결과도 좋아집니다.
- **Copilot이 방향을 놓치면 큰 작업을 더 작은 프롬프트로 나눕니다.**
- **적용하기 전에 변경 내용을 검토합니다** — 나중에 다시 작성하는 것보다 생성된 코드를 미리 확인하는 편이 빠릅니다.
- **구현 단계마다 바로 앱을 테스트합니다** — 그래야 문제의 범위를 좁게 유지할 수 있습니다.

- 구현, 검토, 테스트, 개선을 아우르는 **전체 기능 개발 흐름**
