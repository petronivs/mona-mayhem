# 파트 5: 다듬기 및 병렬 작업

---

앱이 작동하고 보기에도 좋다면 이제 마무리할 차례입니다. 이 파트에서는 반응형 동작, 오류 처리, 품질을 개선하는 작업을 나누어 한 번에 순차적으로 처리하지 않고도 결과를 다듬습니다.

<!-- track:vscode:start -->
## 작업 1: 반응형 디자인용 백그라운드 에이전트

1. 채팅 패널에서 **+**를 클릭해 새 채팅을 엽니다.
2. 창 아래쪽에서 **Local**이 **Copilot CLI**로 바뀌는 것을 확인합니다.
3. 다음 프롬프트를 입력합니다.

   ```
   반응형 CSS 미디어 쿼리를 추가합니다. 1024px에서는 비교 영역을 한 열로 바꾸고,
   768px에서는 글꼴 크기를 줄이고 입력란을 세로로 쌓아 모바일에서도 사용하기
   편하게 만듭니다. 키보드 접근성도 개선합니다. 탭 순서가 올바른지 확인하고,
   Enter 키로 배틀을 실행하며, 포커스 상태가 보이도록 합니다.
   ```

4. 독립적으로 작업하도록 둡니다. 진행 상황을 계속 지켜볼 필요는 없습니다.
5. 작업이 끝나면 변경 내용을 **Review**하고 **Apply**를 클릭합니다.

## 작업 2: 오류 UX 개선용 백그라운드 에이전트

1. 다른 백그라운드 에이전트를 시작합니다.
2. 다음 프롬프트를 입력합니다.

   ```
   오류 경험을 개선합니다. 오류가 발생할 때 흔들리는 애니메이션을 추가하고,
   아케이드 테마에 어울리는 빨간색(#ff3366) 네온 글로우 효과가 있는 오류
   메시지를 디자인하며 입력 유효성 검사 피드백을 개선합니다. 사용자 이름이
   비어 있거나 유효하지 않을 때 명확한 오류 메시지를 표시합니다.
   ```

3. 에이전트가 완료되면 변경 내용을 검토하고 **Apply**를 클릭합니다.

## 작업 3: 변형을 위한 클라우드 에이전트(선택 사항)

1. 채팅 패널에서 **+**를 클릭해 새 채팅을 엽니다.
2. 창 아래쪽에서 **Local**이 **Cloud**로 바뀌는 것을 확인합니다.
3. 다음 프롬프트를 입력합니다.

   ```
   배틀 페이지에 사용할 대체 색상 테마를 만듭니다. 레트로 아케이드 스타일은
   유지하되 초록색과 보라색 대신 파란색(#00f5ff)과 주황색(#ff6b35)을 사용합니다.
   전환할 수 있는 CSS 사용자 지정 속성 테마로 구현합니다.
   ```

4. 진행 상황을 확인하려면 **agent sessions**를 살펴봅니다.
5. 클라우드 에이전트가 만든 PR에서 디자인 변형을 검토합니다.

## 작업 1: `/fleet`으로 작업 분담

Copilot CLI에서 `/fleet`을 사용해 여러 하위 에이전트(subagent)에 작업을 나눈 다음 결과를 함께 검토합니다.

```text
/fleet 앱을 병렬로 개선합니다.
1. 반응형 CSS 미디어 쿼리를 추가해 1024px에서 비교 영역을 한 열로 바꾸고, 작은 화면에서는 입력란을 세로로 쌓습니다.
2. 키보드 접근성과 포커스 표시를 개선합니다.
3. 유효성 검사 피드백과 아케이드 스타일의 네온 오류 상태를 개선합니다.
```

CLI가 작업을 조정하도록 한 다음, 변경 내용을 승인하기 전에 `/diff`로 결과를 확인합니다.

## 작업 2: 변형 작업 위임(선택 사항)

비동기 클라우드 워크플로를 사용해 보고 싶다면 디자인 변형을 위임합니다.

```text
/delegate 레트로 아케이드 분위기는 유지하면서 파란색(#00f5ff)과 주황색(#ff6b35)을 적용하는 배틀 페이지의 대체 색상 테마를 만듭니다. 쉽게 전환할 수 있게 합니다.
```

위임한 작업은 별도로 검토할 수 있는 pull request를 만들어야 합니다. 그동안 로컬 작업을 이어 갈 수 있습니다.

## 작업 3: 에이전트 기반 검토

작업을 마무리하기 전에 Copilot CLI에 검토를 요청합니다.

```text
/review 현재 브랜치에서 발생할 수 있는 버그, 접근성 문제, UX 회귀를 중점적으로 검토합니다.
```

검토 결과를 확인하고 동의하는 문제를 수정한 다음 `/diff`를 다시 실행해 변경 내용을 확인합니다.

## 작업 4: 전체 확인
<!-- track:cli:end -->

> **⚠️ 변경 사항이 보이지 않나요?** 다듬기 작업의 결과가 보이지 않으면 개발 서버를 중지(`Ctrl+C`)하고 `npm run dev`로 다시 시작한 다음 브라우저에서 강력 새로 고침(`Ctrl+Shift+R`)을 합니다.

다음 시나리오를 테스트해 모든 기능이 작동하는지 확인합니다.

| 테스트 | 예상 결과 |
|------|----------------|
| 입력란을 비운 채 Battle 클릭 | 흔들리는 애니메이션과 스타일이 적용된 오류 표시 |
| 유효한 사용자 이름 | 기여도 그래프 표시 |
| 잘못된 사용자 이름 | 레트로 스타일이 적용된 API 오류 표시 |
| 입력란에서 Enter 키 누르기 | 배틀 실행 |
| 모바일 화면 너비 | 한 열로 표시되는 반응형 레이아웃 |
| 기여도 사각형에 마우스 올리기 | 날짜와 기여 수가 포함된 툴팁 표시 |

프로덕션 빌드를 만들고 오류가 없는지 확인합니다.

```bash
npm run build && npm run preview
```

모든 항목이 만족스러우면 작업 코드를 커밋합니다.
