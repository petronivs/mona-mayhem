## 🏆 과제 1: 승자 배너

두 기여도 그래프가 로드되면 총 기여 수를 비교해 승자를 동적으로 알립니다.

**구현할 내용:**
- 두 사용자의 총 기여 수를 비교합니다.
- 승자가 명확하면 축하 스타일로 **"🏆 {username} WINS! 🏆"**를 표시합니다.
- 기여 수가 같으면 **"🤝 IT'S A TIE! 🤝"**를 표시합니다.
- 더 신나는 효과를 원하면 애니메이션이나 색종이 효과를 추가합니다.

**프롬프트 예시:**
> 두 사용자의 기여도 데이터를 모두 불러온 뒤 총 기여 수를 비교하고 승자 배너를 표시합니다. 한 사용자의 기여 수가 더 많으면 "🏆 {username} WINS! 🏆"를, 같으면 "🤝 IT'S A TIE! 🤝"를 표시합니다. CSS 애니메이션을 사용해 시각적으로 인상 깊게 만듭니다.

## 🏆 과제 2: 연속 기록 카운터

각 사용자의 가장 긴 연속 기여 기록을 계산해 표시합니다.

**구현할 내용:**
- 날짜별 기여도 데이터를 분석합니다.
- 기여가 하루 이상 있었던 날짜가 연속으로 이어지는 가장 긴 기간을 찾습니다.
- 각 사용자에 대해 연속 기록 일수를 눈에 띄게 표시합니다.
- 더 긴 연속 기록을 보유한 사용자를 강조합니다.

**프롬프트 예시:**
> 각 사용자의 기여도 데이터를 분석해 가장 긴 연속 기여 기록을 계산하는 카운터 기능을 추가합니다. 각 사용자의 기여도 그래프 아래에 "🔥 Longest Streak: X days"를 표시합니다.

## 🏆 과제 3: 배틀 기록

배틀 결과를 저장해 이전 대결을 확인할 수 있게 합니다.

**구현할 내용:**
- 각 배틀 결과(사용자 이름, 총 기여 수, 승자, 타임스탬프)를 `localStorage`에 저장합니다.
- 메인 배틀 영역 아래에 **"Recent Battles"** 섹션을 추가합니다.
- 최근 5~10회의 배틀 결과를 표시합니다.
- "Clear History" 버튼을 추가합니다.

**프롬프트 예시:**
> 비교가 끝날 때마다 배틀 결과를 localStorage에 저장합니다. 사용자 이름, 기여 수, 승자, 배틀 시각을 표시하는 "Recent Battles" 섹션을 추가해 최근 10회 기록을 보여 줍니다. "Clear History" 버튼도 추가합니다.

## 🏆 과제 4: 사운드 효과

외부 파일 없이 Web Audio API를 사용해 레트로 아케이드 사운드 효과를 추가합니다.

**구현할 내용:**
- **코인 투입(Coin insert)** — "Battle!" 버튼을 클릭하면 재생합니다.
- **파워 업(Power up)** — 결과를 성공적으로 불러오면 재생합니다.
- **폭발(Explosion)** — 오류(사용자를 찾지 못했거나 API 호출에 실패한 경우)가 발생하면 재생합니다.
- 음소거/음소거 해제 전환 버튼을 추가합니다.

**프롬프트 예시:**
> 오디오 파일 없이 Web Audio API를 사용해 레트로 아케이드 사운드 효과를 추가합니다. 배틀을 시작할 때 코인 투입 소리를 재생하고, 결과가 로드되면 파워 업 소리를, 오류가 발생하면 폭발 소리를 재생합니다. 오실레이터와 게인 노드(gain node)를 사용해 프로그램 방식으로 소리를 생성하고 음소거 전환 버튼도 포함합니다.

## 🏆 과제 5: 애니메이션 배틀 진행

결과를 공개하기 전에 긴장감을 높이는 카운트다운을 표시합니다.

**구현할 내용:**
- "Battle!"을 클릭하면 전체 화면 오버레이를 표시합니다.
- **"3..."** → **"2..."** → **"1..."** → **"⚡ FIGHT! ⚡"** 애니메이션을 표시합니다.
- 그 후 극적인 등장 효과와 함께 기여도 그래프를 표시합니다.
- CSS 애니메이션 또는 JavaScript 타이밍을 사용합니다.

**프롬프트 예시:**
> 사용자가 "Battle!"을 클릭하면 애니메이션 배틀 시퀀스를 추가합니다. 오버레이에 "3..." 다음 "2...", "1...", "⚡ FIGHT! ⚡" 순으로 표시하고 각 단계는 약 1초 동안 보여 줍니다. 카운트다운이 끝나면 슬라이드 인 애니메이션으로 결과를 표시합니다.

## 🏆 과제 6: 기여도 범례

기여도 그래프의 색상 팔레트에 맞는 색상 단계 범례를 추가합니다.

**구현할 내용:**
- 기여 강도를 표시하는 가로 범례를 추가합니다.
- **"Less"**부터 **"More"**까지 레이블을 표시합니다.
- GitHub 기여도 API 응답에서 실제 색상 팔레트를 사용합니다.
- 기여도 그래프 근처에 범례를 배치합니다.

**프롬프트 예시:**
> API의 색상 팔레트에 맞는 색상 범례를 그래프 아래에 추가합니다. API에서 실제로 반환된 기여 수준별 색상과 일치하도록 가장 옅은 색의 "Less"부터 가장 진한 색의 "More"까지 사각형을 한 줄로 표시합니다.

## 🏆 과제 7: 결과 공유

한 번의 클릭으로 배틀 결과를 공유할 수 있게 합니다.

**구현할 내용:**
- 배틀이 끝나면 **"📋 Share Results"** 버튼을 표시합니다.
- 클립보드에 요약 내용을 형식에 맞게 복사합니다.
- 두 사용자의 이름, 기여 수, 승자를 포함합니다.
- 복사가 끝나면 잠시 **"Copied!"** 확인 메시지를 표시합니다.

**프롬프트 예시:**
> 형식이 지정된 배틀 요약을 클립보드에 복사하는 "📋 Share Results" 버튼을 추가합니다. 요약에 두 사용자의 이름, 총 기여 수, 승자를 포함합니다. Clipboard API를 사용하고 복사 후 "Copied to clipboard!" 확인 메시지를 잠시 표시합니다.

## 💻 CLI 추가 기능

핵심 워크숍을 마친 후 Copilot CLI 기능을 더 살펴보려면 다음을 시도합니다.

- `copilot -p "Write a conventional commit message for the current git diff"`로 한 번에 답변만 생성한 뒤 Git에 붙여 넣을 커밋 메시지를 작성합니다.
- `/share file`을 실행해 나중에 참고할 수 있도록 세션을 Markdown으로 저장합니다.
- `/session` 및 `/session plan`으로 CLI가 현재 작업을 추적하는 방법을 살펴봅니다.

### 만든 결과물

- 디자인 사양에 따라 완성한 **다중 페이지 웹 애플리케이션**

- 실제 GitHub 기여도 데이터를 가져와 비교하는 **배틀 아레나**
- 색상으로 활동 수준을 구분하는 **인터랙티브 기여도 그래프**
- **오류 처리, 로딩 상태, 접근성 개선**
- 여러 기기에서 작동하는 **반응형 디자인**

| 기술 | 실습 내용 |
|---|---|
| **컨텍스트 엔지니어링(Context Engineering)** | Copilot에 적절한 파일, 지침, 제약을 제공했습니다. |
| **계획 수립** | 코드를 작성하기 전에 구현 계획을 만들고 다듬었습니다. |
| **에이전트 기반 코딩(Agentic Coding)** | 여러 파일과 단계로 이루어진 작업을 Copilot에 위임했습니다. |
| **디자인 반복 개선** | 시각적 방향을 정하고 결과물을 세련되게 다듬었습니다. |
| **검토 원칙** | 커밋하기 전에 AI가 생성한 변경 내용을 확인했습니다. |
